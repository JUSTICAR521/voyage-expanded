# Voyage Expanded development

This is the single editable source for Voyage Expanded. Git branches handle development. `build.mjs` generates `../dist/Voyage Expanded` and `../dist/Voyage Expanded.zip`; these outputs are ignored by Git. Do not edit generated files independently.

Run `npm run build` and `npm test` from the repository root with Node.js 24+. No package installation is required. Load this folder unpacked only when developing; keep the release build disabled at the same time. A separate unpacked installation has separate browser storage.

`expanded-core.js` owns browser-wide preferences and module start/stop lifecycles. `expanded-settings.js` is the always-available Settings shell. `voyage-adapter.js` registers Inventory; `time-adapter.js` installs the clock controller, which `journal-panel.js` registers as Journal under the legacy `time` preference key. Upgrades preserve the player's prior switch value. Campaign item records remain in the existing Inventory core/worker, independently of the switches.

Inventory data planning is separated from the UI and the Voyage adapter. The MAIN-world bridges read Voyage's runtime and use native editor/inventory functions; the isolated scripts own the extension UI and local records. Do not use the same script path in both execution worlds: Chromium deduplicates content-script paths. `build.mjs` maintains the identical `inventory-core-main.js` and `journal-core-main.js` copies.

`journal-core.js` selects exact native turn objects plus narrowly scoped observations of inventory, visible quests, and clock; it excludes party memory and hidden quest definitions. `journal-store.js` serializes appends to per-record `chrome.storage.local` keys and a campaign/party index. Native turn hashes detect revisions, while generated record IDs keep originals, observations, and successive player-entry edits independent. Compaction never deletes stored originals. Queries load pages rather than returning the entire archive to the UI. Unknown historic dates remain null, recovered quest markers can appear without an original story, and multi-turn observations retain their range.

`inventory-worker.js` imports `journal-core.js`, `journal-store.js`, and `journal-worker.js`. Journal worker messages are separate from Inventory's port protocol. The worker owns a short recording lease per campaign, serializes archive operations, and exports chunks of at most 100 records. Automatic backups trigger after 100 unbacked original-turn records; notes/events join the backup without increasing that turn count. Only completed browser downloads acknowledge records as backed up; exports never prune them. Manual export includes the full archive. Import validates matching identity/content and adds or repairs records without overwriting an observed local timeline. Imports and captures do not mutate native game state.

Keep a single package for Production, Beta, Alpha, and Preview. Both script worlds match the root Voyage host and its subdomains, including nested Preview hosts. Inventory record identity is shared across environments within an installation; do not add the hostname to campaign keys. Preserve stale-state and operation checks: matching hosts and successful startup do not prove that a save can safely move between environments. The public guide documents this limitation, and `../VALIDATION.md` records live testing separately from URL coverage.

`npm run preview` serves a disposable UI fixture at `http://127.0.0.1:8774/play?saveId=90001&tree=journal&nativeLine&journal`. Its Journal controls advance synthetic turns, compact native history, and change inventory between turns. The actual recorder, storage, and worker run against simulated transport/downloads and localStorage persistence. It never connects to a real campaign. The existing Inventory fixture remains available with `?saveId=90001&tree=modules&cards&nativeLine`.

Before a release: rebuild, run the suite, test both modules enabled/disabled and native-inventory visibility in a browser, inspect Apply / Cancel / Discard, check clock editing and the location-to-Map shortcut, verify Journal capture/notes/compaction/reload and backup recovery, and check the ZIP. Record the actual scope in `../VALIDATION.md`. A fixture test is not an installed-extension or live-service compatibility test.
